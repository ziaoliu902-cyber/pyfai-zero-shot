## 4. 关键推论：M1cd 的收益来自「先验收缩」而非「不确定性建模」

σ·T 里 T<1 的通道（dist 0.317 / poni 0.53）做两件事：
1. **缩小信任域**（收紧盒子 → 限制搜索）
2. **放大软先验罚项**（σ 变小 → pen=((pn-pn0)/σ)² 变大 → 拉回 NN 粗解）

第 2 项本质是**向 NN 粗解做收缩（shrinkage）**——对中位样本是降方差（好），对尾部是锁死错误（坏）。这正好解释了「中位全线改善、尾部纹丝不动、#321 反而变差 11.78mm」。

验证：用已有 fullpool_dual CSV 算「精修后误差 / NN 误差」的比值分布，并看精修结果与 NN 粗解的相关性。

| 指标 | M1 | M1cd |
|---|---|---|
| dist 误差中位 (mm) | 0.2202 | 0.1836 |
| dist 误差 p90 (mm) | 2.2189 | 2.0666 |
| 与 NN 粗解误差的相关 | 0.4198 | 0.2665 |
| 误差比 (精修/NN) 中位 | 0.1047 | 0.0831 |

→ 若 M1cd 与 NN 粗解误差的相关性**更高**、误差比**更小**，则证实「M1cd = 更强地收缩到 NN」，而非「更好的不确定性建模」。

## 5. 结论与行动项

1. **σ 塌缩 → 信任域是固定盒子**，与样本难度无关；覆盖率低的通道/档位是**结构性不可达**，精修配方无法修复。
2. 应对方向：**按档/按相给信任域设物理半径下限**（`radius = max(trust_k·σ, r_min[channel, tier])`），而不是继续用退化的 σ 调 T。
3. **σ 只应留在软先验里**（作统计权重），不应兼作搜索半径——这与 refine.py 新增的 `sigma_prior` 解耦方向一致。
4. σ 头本身要修：clamp 下限 -6.0 卡掉了 78~100% 样本的真实输出，应放宽下限（如 -12）或改用更稳的不确定性估计（ensemble / MC dropout）。
